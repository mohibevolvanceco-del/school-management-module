Lesson 3: Users, Access and Privacy

Different users, different access

Many people use an SMS, but they should not all see the same things. A teacher needs to mark attendance for their class, but should not change fee records. A parent needs to see their own child's results, but nobody else's. This idea is called role-based access: each user gets only the access their job needs.

UserCan seeCan change
AdminEverythingUser accounts and settings
TeacherTheir own classesAttendance and marks for their classes
Accounts officeFee recordsPayments and receipts
ParentTheir own child's recordsNothing (view only)
StudentTheir own timetable and resultsNothing (view only)

Keeping school data safe

An SMS holds personal data: names, phone numbers, addresses, marks and fee details. If this data leaks or is lost, students and families can be harmed. Good systems protect it in four ways:

  1. Personal logins: every user has their own username and a strong password. Passwords are never shared.
  2. Least access: users only get the access they need (see the table above).
  3. Backups: data is copied regularly, so it can be restored after a crash.
  4. Activity log: the system records who changed what and when, so mistakes can be traced.
Discuss: a teacher leaves the school. What should happen to their SMS account on their last day?
