Lesson 2: Organising School Data

Tables, records and fields

An SMS stores data in tables. Each table holds one kind of thing, such as students or fee payments. Each row is one record (one student), and each column is a field (a detail about that student).

student_idfull_nameclass_idguardian_phone
S1041Ayesha Khan11-A0300-1234567
S1042Hamza Ali11-A0321-7654321
S1043Ayesha Khan11-B0333-1112223

Notice that two students share the name Ayesha Khan. That is why we cannot use the name to identify a student.

Primary keys

A primary key is a field whose value is different for every record. Here, student_id is the primary key: no two students can have the same ID. Roll numbers, receipt numbers and CNIC numbers are all good primary keys.

Foreign keys and relationships

A foreign key is a field that points to the primary key of another table. In the table above, class_id points to the CLASS table. This links each student to their class without typing the class teacher's name again for every student.

The diagram shows four tables in a simple SMS and how they connect:

Figure: how four tables in a school database are linked. PK = primary key, FK = foreign key.

  • One class has many students (one-to-many).
  • One student has many attendance records, one for each school day.
  • One student has many fee records, one for each month.
Why not one big table? If we stored the class teacher's name in every student row, changing the teacher would mean editing 40 rows. With a separate CLASS table, we change it once.
